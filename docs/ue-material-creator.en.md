# ue-material-creator Guide

English | [中文](ue-material-creator.cn.md) | [日本語](ue-material-creator.ja.md) | [한국어](ue-material-creator.ko.md)

This document explains how to use the `ue-material-creator` skill together with the `MaterialSemanticBridge` plugin so an AI Agent can generate, validate, normalize, preview, repair, import, and export Unreal material DSL.

![](../assets/material_cover.png)

## What It Is

`ue-material-creator` is a workflow skill for AI Agents.

It is not Unreal runtime code, and it is not a standalone plugin. Its purpose is to guide an AI Agent to:

- analyze material visual requirements and choose either the `Material` or `MaterialInstanceConstant` workflow
- generate or edit supported indented `.materialdsl`
- work within the documented support surface for `MaterialExpression*`, properties, pins, material settings, graph layout, and material outputs
- validate and normalize DSL before import
- read the material preview images and reports generated by the normalization flow, let the AI Agent visually self-evaluate the result, and repair the `.materialdsl`
- import the stabilized DSL as `Material` or `MaterialInstanceConstant` assets
- export existing materials or material instances back to DSL for continued AI iteration

## Relationship With MaterialSemanticBridge

This setup consists of two parts:

- `MaterialSemanticBridge`: the Unreal Editor plugin responsible for validation, normalization, preview image and report generation, import, export, schema discovery, and editor integration
- `ue-material-creator`: the AI Agent skill responsible for requirement analysis, DSL generation, preview evaluation, and repair workflow

The plugin executes the Unreal-side work. The skill guides the Agent on how to write, check, preview-evaluate, and repair DSL.

## Value for Game Development Productivity

In game projects, materials usually iterate alongside art direction, level environments, performance budgets, and gameplay feedback. Using the `MaterialSemanticBridge` plugin together with `ue-material-creator` turns “describe the material need -> generate DSL -> validate / normalize -> generate a preview image -> AI visual evaluation and repair -> import Unreal assets” into a repeatable workflow, reducing the time spent hand-building nodes, tuning parameters, and organizing material variants.

Typical direct benefits include:

- Faster material prototyping for visual directions such as UI, terrain, stone, metal, fabric, and VFX base materials
- Material visual notes, node graph descriptions, or plain-text requirements can become importable `Material` / `MaterialInstanceConstant` assets more quickly, with less information loss between the idea and the editor asset
- Because material instance parameters are represented as `.materialdsl` text, AI can batch-generate or adjust variants for color, roughness, textures, static switches, and other supported overrides under the same parent material
- The normalization flow can generate material preview images; dynamic materials can also output multi-frame previews, making it easier for AI to check whether motion, flicker, panning, or pulse effects match expectations
- Even if you are not a technical artist, you can use this skill and plugin to create material effects that are closer to the request
- After batch-exporting existing materials or material instances, AI can continue from real project assets instead of guessing from a blank graph
- Material DSL works well with version control and code review, giving technical artists, programmers, and AI Agents a readable shared artifact
- Once repetitive material setup, variant generation, and synchronization are handled by the plugin and skill, developers can spend more time on art judgment, performance tradeoffs, and runtime presentation

## Installation

### 1. Install the Plugin

Plugin address: [MaterialSemanticBridge](https://www.fab.com/listings/cb2fcfbe-a4db-4dee-a9cf-8bbe62823418)

If the plugin comes from Fab, it is usually installed into the Unreal Engine directory with `Install to Engine`.

`MaterialSemanticBridge` supports both installation modes:

- project plugin: `<Project>/Plugins/MaterialSemanticBridge`
- engine plugin: `<Engine>/Plugins/.../MaterialSemanticBridge`

After installation, enable the plugin in your project: in Unreal Editor, go to `Edit` -> `Plugins`, find `MaterialSemanticBridge`, and enable it.

### 2. Place the Skill

In Unreal Editor, open `AIBridge` -> `Material Semantic Bridge`, then use `Download Agent Skill` to download the skill into your project. The default `Destination Root` is the project root, but you can click `Browse` to choose another folder:

![](../assets/ue-material-creator-download-skill.png)

Keep the target that matches the Agent tool you use:

- Codex / Gemini CLI / Cursor / GitHub Copilot / OpenCode and other `AGENTS.md`-compatible Agent tools: `.agents/skills/ue-material-creator/`
- Claude Code: `.claude/skills/ue-material-creator/`

You can also download the ZIP file directly from [GitHub](https://github.com/jokance/ue-ai-semantic-bridges/tree/main), unzip it, and copy the `skills/ue-material-creator` directory into the corresponding `skills` directory:

![](../assets/download-github-skill.png)

It is recommended to keep it in the project repository so teammates and automation environments can share the same workflow instructions.

## Suitable Use Cases

Good fits:

- creating new `.materialdsl`
- editing existing `.materialdsl`
- converting material visual notes or shader graph descriptions into importable material DSL
- checking whether a node class, property, pin, material setting, or output is supported
- validating, normalizing, generating preview images, and repairing material DSL based on the preview result
- exporting existing materials or material instances back to DSL for continued AI editing
- batch-exporting material DSL under `/Game`, or importing only newly created / updated DSL files

Not suitable for:

- runtime material instance parameter changes
- arbitrary HLSL outside the support surface; only supported `MaterialExpressionCustom` usage should enter DSL
- Niagara, UMG, Blueprint, Sequencer, or MetaSound DSL
- unrelated Unreal C++ changes

## How an AI Agent Should Use This Skill

Recommended workflow:

1. Use the repository root as the Agent working directory.
2. Explicitly tell the Agent to use the `ue-material-creator` skill.
3. Ask the Agent to generate or modify `.materialdsl`.
4. Ask the Agent to run the normalization flow; it validates the DSL first, then generates normalized DSL after success, and outputs material preview images when rendering is available.
5. Ask the Agent to read the preview image or multi-frame preview and self-evaluate the material against the request; if the visuals do not match expectations, repair the DSL and normalize again.
6. After both DSL and preview result pass, ask the Agent to import the stabilized DSL into Unreal.

Example (Codex):

1. Use the `$` symbol to select the `UE Material Creator` skill (make sure the skill is correctly placed under the Codex working directory), then press Enter:

## Outputs

Common outputs include:

- DSL files: `.ue_dsl/MaterialDSL/.../*.materialdsl`
- imported materials: `/Game/.../M_*`
- imported material instances: `/Game/.../MI_*`
- normalization, validation, import, or export reports
- material preview PNG: `Saved/MaterialSemanticBridge/MaterialDSLPreview/...`

Static materials usually output one preview image; dynamic materials with time-driven expressions may output multi-frame previews.

## Editor Panel Guide

After enabling the plugin, open the main panel from:

- main menu: `AIBridge` -> `Material Semantic Bridge`

The panel uses unified routing:

- `Export All DSLs`: exports `MaterialInstanceConstant` assets and supported `Material` graphs under `/Game`, preserving the `/Game` subdirectory structure
- `Import New/Changed DSLs`: imports newly created or updated DSL files and routes each file to the matching target asset type
- `Import DSL`: validates and imports a single `.materialdsl` into its auto-mapped target asset
- `Export DSL`: exports a selected `Material` or `MaterialInstanceConstant` to its mapped `.materialdsl`

Single-file and batch workflows do not require the user to choose “material instance” or “material graph” manually. The plugin routes by DSL content or selected asset type.
